# 教训索引（index）

> **层级**：L3 入口。`knowledge/lessons/errors.md` 命中 `[Exxx]` → 在本文件查对应**教训 ID（Lxxx）** → 到 `knowledge/lessons/root-causes.md` 读根因与修法。
> **原则**：**现象（E）多条，根因（L）归并**——同一根因只留一条教训，避免索引膨胀。
> **本文件是 skill 自带的只读基线**：运行期不写；本项目新增的教训写工作空间的 `.afsim-forge/lessons/`（同构）。

---

## 用法

```
errors.md  [Exxx]
     ↓ 本文件
index.md   Lxxx
     ↓
root-causes.md  根因 + 修法 + 生成期预防
```

**新增教训时**（写入**工作空间**的 `.afsim-forge/lessons/`，skill 目录只读）：

1. **首次使用先建同构副本**：把 skill 的 `knowledge/lessons/{errors,index,root-causes}.md` 三个文件**复制**到 `.afsim-forge/lessons/` 下（同名），之后只改副本 —— 这样结构、编号、格式都与基线一致，回流时也好比对。
2. 在 `.afsim-forge/lessons/errors.md` 加 `[Exxx]`（现象）。
3. 在 `.afsim-forge/lessons/index.md` 加行（**能归并到已有 `Lxxx` 就不新建**）。
4. 在 `.afsim-forge/lessons/root-causes.md` 补段落（若为已有教训的补充，只在其「案例」下追加一行）。

> **编号不冲突**：副本从基线末尾接着编号（`E105`、`L012`…）。

## 与知识层的分工

| 问题类型 | 去哪 |
| :-- | :-- |
| "**为什么**会错 / 怎么避免" | 本索引 → `root-causes.md` |
| "**正确写法**是什么" | `knowledge/*.md` |
| "**结构**该放哪" | `blueprints/layout/layout.md` |
| "**报错关键字**对应哪条" | `knowledge/lessons/errors.md` |

> 教训库是**经验**（本项目踩过的坑）；知识库是**规范**（语言与 API 的权威描述）。两者互补，不重复。
