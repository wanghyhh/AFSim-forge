## 三、保真验证

`verify_corpus.py` 把每条摘抄的 `**出处**` + 围栏片段与 `demos/` 原文**逐字节**比对。
比对前对**源文与本库同时施加同一脱敏规则**（移除注释中的 3 处受控标记片段，规则见 `gen_all.py` 的 `SANITIZE`），因此口径一致、仍为严格逐字节：

## 四、覆盖边界（如实说明）

### 4.1 已覆盖

- demo 中出现过的**全部** 449 种块类型、49,816 个块 —— 按签名去重后语法形态**一条不缺**。
- demo 中出现过的**全部** 2,256 个命令 / 参数名 —— 均可从 `90-tokens.md` 反查。
- 缩进、注释、续行、行尾空格**原样保留**，因此「这段到底该怎么排版」也能从片段直接看出。

### 4.2 未覆盖 / 覆盖不足

| 情形 | 说明 | 应对 |
| :-- | :-- | :-- |
| demo 里没有的合法语法 | 新版本新增命令、冷门类型、未在 demo 使用的参数组合 | 以 AFSIM 手册为准，改完**必须**走语法校验 |
| 参数取值域 | 片段只展示 demo 用过的值，不列出全部可选值 | 查手册，或按同类片段推演后校验 |
| 装配关系 | 片段是「块」，不含「谁 include 谁」的全貌 | 结构看 `blueprints/layout/`，或看 `01-structural.md` |
| 外部数据表 | `common/` 里的 `WSF_RADAR_SIGNATURE` / `WSF_AERO` 等表文件内容 | 表格式看 `19-table.md`；数据本身须人类提供 |
| 语义正确性 | 语法对 ≠ 想定对（如航迹能报但报错对象） | 本库不解决语义问题，见 `knowledge/` |

### 4.3 已知取舍

1. **同签名只留 1 条**：若你想看「同一语法在不同工程里的不同用法」，需按 `**出处**` 回原文，或到 `demos/` 直接搜。代表条目已注明「同签名共 N 处，另见 …」给出 3 个替代出处。
2. **代表选取规则**：子参数最多 → 行数最少。因此代表条目**偏向参数最全的写法**，不一定是最短示例；想看最简写法请按出处回原文找短块。
3. **`01-structural.md` 是手工条目**（4 条），讲 `file_path` / `include_once` / 装配骨架，这类「没有 `end_` 闭合」的顶层指令**无法被块扫描器识别**，故人工撰写。
4. **受控标记已清除**：源 demo 中 4,740 / 4,749 个 `.txt` 的文件头带横幅。摘抄一律从**块起始行**开始，横幅位于文件头，因此**横幅从未进入本库**；另有 3 行块内注释残留标记片段，已在生成时按 `gen_all.py` 的 `SANITIZE` 规则移除。**全库不含任何受控 / 分级 / 分发限制字样**，按公开信息处理。
