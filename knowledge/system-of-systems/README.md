# system-of-systems — 体系仿真知识

> **本目录回答"体系级怎么设计"**：多平台如何编成一套体系、信息如何流动、任务如何分配、效能如何度量。
> **不含**语法与参数（去 `../language/`、`../blocks/`），**不含**目录结构与骨架（去 `../../blueprints/`）。

---

## 1. 先读哪篇

| 你的处境 | 读这篇 | 作用 |
| :-- | :-- | :-- |
| **第一次做体系工程**，不清楚"体系仿真"与"平台仿真"差别 | `concepts.md` | ★ **入口篇**：体系 vs 平台、三层结构、四类关键关系、建模顺序 |
| 要**搭指挥关系**（谁管谁、任务怎么下发、航迹怎么上报） | `command-chain.md` | `command_chain` / `commander` 三种写法、任务下发与回报、态势共享 |
| 要**闭合杀伤链**（发现→定位→跟踪→交战→评估） | `kill-chain.md` | 杀伤链五环、处理器链、关键事件、断链分析 |
| 要让**雷达/传感器组网**（跨平台共享航迹、通信能不能通） | `sensor-network.md` | 三层通信结构、`network`/`comm`/`medium` 写法、平台内 `internal_link`、通不了怎么排查 |
| 要**定义任务类型**（侦察/打击/拦截/评估…） | `task-taxonomy.md` | `taskTypeId` 取值表、与工程结构的关系 |
| 要**设计效能指标**（闭合率、反应时间、生存率） | `kpi-metrics.md` | 指标分层、定义、事件对照表、事件输出配置建议 |

---

## 2. 阅读顺序（推荐）

```
concepts.md（建立框架）
    ├─ command-chain.md    指挥链 ──┐
    ├─ sensor-network.md   信息流 ──┼─→ kill-chain.md（三者合成一条链）
    └─ task-taxonomy.md    任务   ──┘
                                    └─→ kpi-metrics.md（怎么量它好不好）
```

**建模顺序**（`concepts.md` §4 的落地版）：阵营与平台实例 → 指挥关系 → 通信组网 → 传感器与武器 → 任务与脚本 → 指标与事件输出。

## 3. 事实依据与可信度

| 标记 | 含义 | 怎么用 |
| :-- | :-- | :-- |
| 无标记 | 有实测/官方语料依据 | 可直接用 |
| **「待校验」** | 来自推断（样例反推或通用方法论） | 可参考，**不作唯一依据**；与 `blueprints/cases/` 实测案例冲突时**以案例为准** |

各篇开头都注明了素材来源（样例工程的具体文件），便于回溯核对。

---

## 4. 本目录**不做**的事

- **不负责仿真后分析**：`kpi-metrics.md` 只用于**设计期预留指标口径**（如配好 `event_output` 输出项）；跑仿真与取结果仅在交付后按用户要求进行。
- **不替代结构规则**：`sensor-network.md` 讲"信息流该怎么设计"，但 `network/*.txt` 具体放哪、`medium.txt` 怎么汇总，以 `blueprints/layout/layout.md` 为准。
